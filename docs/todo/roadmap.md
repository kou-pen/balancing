# 開発ロードマップ

まず**固定脚長で安定して倒立・走行・停止できること**を目指します。可変脚長とジャンプは、その後の段階です。

## 3つの段階

| 段階 | 達成したいこと | 完了の基準 |
|---|---|---|
| **P0：固定脚長** | 起動、倒立、前後走行、旋回、安全停止 | 支持治具から始め、実機で再現・計測できる |
| P1：可変脚長 | 目標脚長を変えながら安定化 | 現在脚長を初期目標にした制御とゲイン補間を検証 |
| P2：ジャンプ | 離陸・着地・復帰 | 段階的な実機試験で安定動作を確認 |

## P0の現在地（2026-11-27）

CAN2通信と通常運転の周期経路をホストで結合済み。USB Host・表示・IWDG・独立試運転の起動経路を実装し、通常停止専用送信もホスト検証した。ARM準備診断、周期送信管理共通化、車輪原点再設定、通常/SIL駆動実行の共通化、単軸試運転の明示操作接続もmasterへ反映済み（#90〜#95）。実機設定と物理モデル、ARM・通常駆動出力は未接続。実機駆動は未検証。

| 領域 | ホストで成立している範囲 | 残る作業 |
|---|---|---|
| CAN・モータ | 両CAN起動、Router、送信調停、6軸観測、RS06有効化・停止、C620連続性、通常指令250/500Hzの模擬送信・終端・停止 | 通常停止専用は実装済み（既定無効）。実機ARM・非ゼロ出力の接続、通信・周期・負荷 |
| センサ・制御 | BNO055非同期取得、状態推定、脚運動学fixture、500 Hz SIL、LQR/VMC・脚PD/Roll・Yaw、6軸指令換算 | CAD定数・実機原点・ゲイン、実機用制御周期 |
| Application | 非駆動観測、CAN2操作/電源/診断、通常運転SILと6軸模擬送信 | 実USB列挙・操作、実機用モデルと出力許可 |
| 自作CAN2 | 35 ID codec、12受信ID、電源・操作・診断のApplication結合、明示フィルタ、背景送信をホスト検証 | 実機起動設定、通常モータ送信との実時間計測、F303/Pi互換性。追加診断値は必要になるまで保留 |

## P0の開発方針（ユーザー承認 2026-11-27）

**ロボットを起動・操作・駆動・安全停止するために直接必要な機能を優先する。** 実機データ・CAD・実測値が必要な作業は資料と実機が揃うまで保留する。既存の安全条件・送信監視・FAULT通知・試験の受入条件は維持し、診断を省くことを理由に安全機構を弱めない。

| 区分 | 扱い |
|---|---|
| 運転状態・FAULT原因・電源状態、操作と停止 | 必要な最小限を維持・接続 |
| 姿勢・車輪・脚などの観測、実測ログ | 調整・検証に必要な範囲で利用。実機データ依存は保留 |
| CONTROL_TIMING追加配信、詳細購読拡充、設定読出し番号、ARM準備ビットや軸別の追加診断 | 保留。具体的な必要性が生じたときだけ別途検討 |
| 既存の診断コード・承認済みCAN ID | 削除・再割当しない。既存仕様と未完了項目を保持 |

## P0の残りの開発順序

番号は作業のまとまり。1機能1 PR、ソース・試験・文書のコミット分離を維持する。細分化や汎用化それ自体を目的にしない。各項目の実機非依存部分から進め、実機許可・安全条件は別途承認する。2026-11-27のユーザー指示により、F446の実機非依存タスクの後はF303電源基板FWを優先し、Raspberry Pi通信・操作はその後に着手する。

| 順序 | 作業単位 | 実機なしで進める範囲 | 関連TODO |
|---:|---|---|---|
| 1（#94統合済み） | F446通常駆動処理の統合 | 既存SILの制御・6軸指令・送信終端・停止処理を活用し、実機非ゼロ出力を無効のまま共通処理を統合 | T-F446-03/04/08〜10、T-CTRL-11 |
| 2（#95統合済み） | 単軸試運転の操作経路 | 既存BenchDebugで明示操作と停止を模擬検証。実機入力・出力許可は別承認 | T-F446-11/12 |
| 3（#97統合済み） | 起動処理の統合 | 既存起動順・排他性を維持し、初期化失敗の伝達を整理。実機設定は保留 | T-F446-01/02/06 |

CAN2通信、DualSense論理操作、表示・安全監視の既存ホスト検証は再実装しない。統合に必要な不足だけを扱う。

実機データ依存の六節リンク・機構干渉・LQRゲイン・原点・符号・トルク/電流上限、電源回路の保護条件、実機検証は保留する。資料と実機が揃った後に回路・CAD・原点・符号・低出力単軸試験・通信負荷・安全停止・倒立の順で進める。ホスト段階の合格だけで実機を許可しない。**P0完了条件はARM・姿勢保持・前後走行・旋回・DISARM/FAULTを実機で再現し、電流・トルク・周期・ログを残すこと。**

### F446からF303への移行（2026-11-27）

#97起動処理、#98立ち上げ文書、#99数学LQR、#100補償IFを統合。IMUと電源状態の期限切れ独立SILをレビュー版で追加し、CTest 81/81。実機・CAD・計測依存の残件はチェック欄を維持したまま保留する。F303全10設計と電源論理コアを#103で統合し、PowerMonitorの換算・状態別保護を#104で統合し、既存電源Codec共用のPowerCan・F446対向試験を#105で統合し、BoardIO論理出力とLEDを#106で統合し、CubeF3 HAL/CMSIS導入・ARMリンク試験を確認。次はapplicationの論理統合とCubeMX生成・実GPIO接続。実機の電源制御・閾値は別承認。

## 次の段階と前提

P1では、MOTOR-159の決定どおり**ARM時の脚長目標は現在脚長**にします。可変脚長でのゲイン補間などの詳細は [制御TODO](control.md) にあります。P2は [ジャンプTODO](jump.md) を参照してください。

再起動時のFAULT復元（MOTOR-095）と起き上がり手順（MOTOR-132）は保留です。RS06原点、駆動符号、機械特性、トルク上限、実機用LQRゲインも未検証のままです。確定事項と未検証事項は [仕様ID索引](../spec-index.md) と [検証記録](../verification/index.md) から追跡できます。
