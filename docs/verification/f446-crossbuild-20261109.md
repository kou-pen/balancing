# STM32F446ヘッドレスクロスビルドの検証記録

**検証日:** 2026-11-09  
**関連:** Issue #3、T-F446-13/14、BOARD-F446-001  
**実施環境:** Balancing Development VM（Ubuntu x86_64）、STM32CubeIDE 1.19.0、IDE同梱GNU Tools for STM32 13.3.rel1  
**対象:** `firmware/f446/balancing_f446`。書込み・通電・モータ指令は未実施。

## 再現手順

```sh
cd /home/dev-admin/chatgpt-workspace/balancing
python3 tools/sync_cubeide_cpp.py
/opt/st/stm32cubeide_1.19.0/headless-build.sh \
  -data "$PWD/build/cubeide-issue3-reproduce" \
  -import "$PWD/firmware/f446/balancing_f446" \
  -build balancing_f446/Debug
/opt/st/stm32cubeide_1.19.0/headless-build.sh \
  -data "$PWD/build/cubeide-issue3-reproduce" \
  -import "$PWD/firmware/f446/balancing_f446" \
  -build balancing_f446/Release
```

既に実行した計測ではDebug/Releaseを別々の新規Eclipseワークスペースでビルドした。ビルド出力はそれぞれ `firmware/f446/balancing_f446/Debug` と `Release`。生成物はGitへ登録しない。

## 結果

| 項目 | Debug | Release |
|---|---:|---:|
| ELF生成 | PASS | PASS |
| コンパイルエラー | 0 | 0 |
| コンパイル警告 | 0 | 0 |
| C++アプリの実際のオプション | `-std=gnu++17` | `-std=gnu++17` |
| text | 15,708 B | 9,216 B |
| data | 12 B | 12 B |
| bss | 2,820 B | 2,820 B |

初回のDebugビルドは `-std=gnu++14` が選択されていた。CubeIDEの `.cproject` で両構成をGNU++17に設定し、再ビルドでコマンドラインが一致することを実測した。 `tools/sync_cubeide_cpp.py` は再生成後にこの設定を検査し、`--fix` で復元する。

## ビルドできた範囲

- CubeMX生成コード、HAL、C++ `App/Src/application.cpp`、Cリンケージのブリッジ、TIM7の500 Hz処理入口
- `main.c` からC++アプリの初期化・周期・ポーリング関数へのリンク
- CAN1/2の初期化関数自体は生成されているが、実運用通信は起動していない

**ビルド対象に含まれていないもの：** `firmware/core/src/balancing_motor_can.c`、`balancing_motor_bench.c` と `firmware/f446/src/balancing_f446_motor_bench_port.c`。これらのモータCAN層はホストの模擬HAL試験のみPASSであり、今回のELFの一部ではない。

## CAN接続上の未完了事項（静的コード確認）

- `HAL_CAN_ConfigFilter`、`HAL_CAN_Start`、`HAL_CAN_ActivateNotification` の呼出しが現状の起動コードにない。
- CAN受信FIFO0割込み、CAN1/2の送信メールボックス0/1/2完了通知をモータCANアダプタへ中継するcallbackは未接続。
- `HAL_CAN_MspInit` 等の生成済み初期化、CANピン、NVIC優先度、CAN1/CAN2の共有フィルタバンク、時刻基準は実基板を使う前に再点検する必要がある。
- 実機用のRS06ホストID、モータFWとの換算、低トルク・低電流上限、物理非常停止入力は未検証。推測で埋めない。

## 合否の境界

今回のPASSは**非駆動のSTM32 ELFをビルドできることのみ**を意味する。実機CAN接続、500 Hz実時間性、CAN送信完了監視、ARM/FAULT、電源遮断、モータの安全停止を保証しない。

次の実装段階では、外部CAN層のMCUリンクと実CAN HAL初期化を個別に検証し、ゼロ出力通信を経て、ユーザーの事前承認のもとで初回の実機試験に進む（Issue #3、T-F446-11/12、T-VERIFY）。実機への書込みは今回の作業範囲外。
