# F446 CAN1/CAN2共通受信ランタイムのホスト検証

仕様：BOARD-F446-001、PROTO-RS06-001、PROTO-C620-001。対象：T-F446-03/05/07、Issue #11/#27。基準：PR #51統合後の `40a3174`。

## 実装と責務

`f446_can1_runtime.cpp` の既存ランタイムを両バスへ拡張した。各バスのCanPort/CanTxSchedulerと監視集計は独立し、DWTの64bit積算時計は一つだけ保持する。CAN1の監視コピーAPIは維持。CAN2は `Can2Observation.h` で受信件数、左右の分類件数、最終RX時刻、受信欠落・bus-off・評価時刻を公開する。分類は標準ID・DLCによるもので、内容の復号や鮮度確認ではない。

### 起動

`balancing_f446_can_start(&hcan1, &hcan2)` は両ハンドル・READY・DWTを先に検査する。共有フィルタを設定し、両CANを起動、割込みから見えるポートを構築してから通知を有効化する。起動完了前は監視コピーを公開しない。途中失敗時は通知を解除して開始済みのバスを停止し、ポートを破棄する。HALのERROR状態などで停止に失敗した場合は起動失敗を保持し、再起動を拒否する。

| バンク | 所属 | 受理 |
|---|---|---|
| 0, 1 | CAN1 | 拡張データ Type 2/24、IDE/RTRを比較 |
| 14, 15 | CAN2 | 標準データ 0x201/0x202、全11bit IDとIDE/RTRを比較 |

共有バンク境界は14。F303・Piの未確定IDは追加しない。CAN2の左右実機ID割当は照合待ち。

### 主ループ

`main.c` と `stm32f4xx_it.c` のUSER CODEのみを変更。CAN2 TX/RX0/SCE IRQではポート取得成功時にHALの二重消費を防ぐ。既存の `pollCanEvents` が両バスを交互に有限回で回収する。回収後に時計を読み、両監視コピーに同一評価時刻を記録。IRQで記録した受信時刻は変更しない。Applicationの既存周期診断APIは変更しない。

## 受入試験

- フィルタの共有境界、バンク番号、ID/IDE/RTR、DLC分類、誤ったハンドル・DWT不可の拒否。
- CAN2フィルタ失敗、起動失敗、通知失敗、通知直後の両バスIRQ、両監視値の公開制限。
- HAL起動タイムアウト（ERROR）と停止失敗を独立プロセスの `--rollback-failure` で再現。CAN1停止、起動失敗の保持、再起動拒否。
- DWT周回、両バスのRXと評価時刻、IRQマスク復元、Applicationの周期差分。
- CAN1/CAN2各々のbus-off/復旧・欠落、CAN1キュー集中時のCAN2回収、両バスの送信メールボックスにTXRQがないこと。

## 検証範囲・残件

通常CANモードのためバス上のACK・エラーフレームまで抑止するわけではない。アプリケーションの送信要求（ゼロ電流を含む）は追加していない。MotorServiceへの機器報告配送、ControlCycleの実機呼出、実IMU、ARM、モータ送信は未接続。Core生成部分、Drivers、.ioc、ピン、USB設定は変更しない。PB12/PB13 CAN2、PB14/PB15 USB HS内蔵FS PHY、VBUS検出無効はコード上で確認したが、現物の回路・給電・終端・通信負荷・実機周期は未検証。DWT周回間隔未満の定期採取が必要。
