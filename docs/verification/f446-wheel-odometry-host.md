# F446 C++17 車輪オドメトリのホスト検証

**対象:** CTRL-EST-001、PROTO-C620-001、Issue #10・#11・#27。  
**ベース:** `master` `47e6f1e`（PR #44統合後）。  
**範囲:** CAN2 C620報告のC11復号 → `MotorService::feedback()` → `WheelOdometry::update()`。実機未接続。

## 実装の呼び出し順と責務

`MotorService` は左右車輪のC620生エンコーダ、RPM、CAN受信時刻、20 ms鮮度を返す。`WheelOdometry` は**前回受理した受信時刻より新しい報告だけ**を読み、折返しと速度換算を行う。上位から同じ報告を何度取得しても位置は二重積算しない。周期の評価時刻は出力に残すが、実際の計測時刻に書き換えない。

校正値（半径、ロータ対車輪の比、方向±1）は構築時に一度だけ検査して固定する。旧C11の `b_observation_wheel()` と異なり、周期内で設定変更を受け付ける入口自体を設けない。`reset()` は積算原点だけを消す。ロータ差分の `±4096` は正逆が一意に定まらないため棄却し、他方の車輪や旧位置は変えない。受信時刻の逆行・未来時刻・範囲外カウントも同様に不採用とする。

出力の `fresh` は `MotorService` 側の鮮度に従い、かつ**最新のCAN報告が実際に換算成功した時刻**に一致する場合だけ真にする。生報告だけ新しくても変換が失敗したときは、古い位置を新しい観測として公開しない。

## 受入ケース

| 試験 | 判定する具体的な挙動 |
|---|---|
| 初回左右、折返し | 左8190→2は+4カウント、右2→8190は-4カウント。左右方向設定により車輪位置の符号を確認 |
| ロータRPMと受信時刻 | 60 RPMから車輪周速度を計算し、元のCAN受信時刻を保持する |
| 同じ報告を再読 | 500 Hz周期で同じ受信時刻を再処理しても位置を加算しない |
| 片軸だけ更新 | 片方の受信更新・失効で他方の位置と受信時刻を変更しない |
| 曖昧な半回転・異常時刻 | 4096差、未来、逆行、8192カウントを棄却し、前回の位置・時刻を保持 |
| 校正が未確認 | 該当軸だけ変換を拒否。リセット後は初回報告を原点0mとする |
| 既存Codec/Serviceとの結合 | 実C11デコーダで0x201/0x202を復号、`MotorService` の左右軸・時刻が新C++17観測に渡る |
| 20 ms境界 | `MotorService` の最新判定に従い、期限ちょうどで新C++17は `fresh=false` |

検証専用の車輪半径 `0.1 m`、比 `10:1`、左右符号 `+1/-1` は**数学fixture**であって実機設定ではない。物理的に半回転未満で毎回受信できる速度・通信周期も未検証である。

## 期限境界の既知差分

| 経路 | 鮮度期限20 msちょうど |
|---|---|
| 旧C11 `b_check_freshness()` | 有効（`<=`） |
| 新C++17 `C620Motor::feedback()` | 失効（`<`） |

このPRでは期限の数値や既存の判断式を変更しない。車輪変換側では独自の20 ms比較を追加せず、すでに取得した `fresh` を再利用する。旧C11との期限境界の一致・安全影響は統合SILで別途判断する。
