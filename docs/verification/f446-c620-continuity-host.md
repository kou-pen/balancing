# C620受信順の累積位置と連続性の検証

仕様：CTRL-EST-001、PROTO-C620-001、BOARD-F446-001。対象：T-CTRL-04、Issue #11/#27。基準：PR #52統合後の `29d7add`。

## 実装の責務

- `C620Motor::onFeedback()`：復号済み報告を受理順に処理し、8192カウントの一周折返しを行う。初回原点は0、符号付き64bit累積値、受理番号、原点世代を保持。同じIRQ時刻の複数報告を捨てない。整数加算の上下限は同じ判定式でコンパイル時に検査。
- `MotorService`：左右の独立した連続性設定を構築時に固定。CAN2のRxLost/BusOffでは両軸、既知標準IDで復号拒否された報告は該当軸の位置連続性を無効化。 `MotorCanLink` がCAN2の状態通知と既知IDの短いDLCも配送する。
- `WheelOdometry`：受理済みの累積カウントを車輪半径、ロータ/車輪比、方向で距離へ変換する。RPMの速度換算は従来式。二重の折返し積算を廃止し、原点世代・受理番号・評価時刻・連続性・校正・通信鮮度を照合する。無効時に診断用の前回位置を保持しても制御に使わない。

`position_m = counts × 2π × wheelRadiusM × direction / (8192 × motorRevsPerWheelRev)`。

## 連続性の契約

`C620ContinuityConfig.maxCaptureGapUs` は検証済みの排他的取得間隔上限。未指定、verified=false、0、20ms超は位置未検証。上限の値は実機の最大ロータ速度・実測報告間隔・CAN伝送とFIFO/IRQ採取遅延を含めて、隣接実測値の変位が半回転未満になることを確認して決める。今回は人工の4msを試験に用いるのみ。現物の上限を確定していない。同時刻は受信順に処理するが同時刻だから実測間隔がゼロとはみなさない。

半回転ちょうど、隣接報告の時刻差が設定上限以上、時刻逆行、角度不正、累積範囲超過、通知された受信喪失で連続性をラッチする。正常報告が戻っても無効のまま。最新報告の通信鮮度（20ms未満）は独立して維持する。設定上限の判定は**隣接報告間の取得時刻差**であり、周期評価時点の追加鮮度期限にはしない。通信が途絶えている間は既存の20ms鮮度で判定し、次の報告が来たとき間隔を検査する。

原点を変える場合は、DISARMEDかつ旧RXキュー排除済みの上位操作から `MotorService::resetWheelReference()` 成功後に `StateEstimator::reset()` を1回呼ぶ。両者は初期世代1を共有し、同じ回数だけ世代を進める。前世代のコピーを新原点にしない。次の新規報告は以前の採取時刻より新しい必要がある。実機での操作・キュー排除の呼出は未接続。上位のこの前提をAPI自身が検証するわけではない。

## 受入試験

| ケース | 観測結果 |
|---|---|
| 0→3000→6000、2報告後の一回コピー | +6000 count、旧方式の−2192を回避 |
| 同じIRQ時刻、正逆周回、コピー再読 | 別受理番号で積算。再読では積算しない |
| 半周差、上限ちょうど、逆行、不正原値、未検証設定、未来時刻 | 位置拒否。整数加算境界はstatic_assert |
| 短いDLC、CAN2 RxLost、BusOff/復旧 | 模擬FIFO→Router→MotorService→WheelOdometry。残存RXでも連続性が戻らない |
| 原点再設定と旧世代 | 明示同期と新規報告でのみ位置再成立 |
| 500Hz SIL | 車輪の通信鮮度が有効でも連続性喪失で既存のInterlockLost経路に入り、数学指令を返さない |

## 限界・非変更

C620は送信連番を持たないため、未検出のフレーム欠落やセンサ実測時刻は受信時刻だけでは保証できない。CanPortが既存の仕様で破棄するRTRやDLC>8は、この機能では個別の車輪異常として識別しない。実機最大速度・取得間隔・軸ID・物理パラメータは未検証。新しいFAULT種類・実機安全閾値・駆動指令・CAN HAL・Core/Drivers・C11基準を変更しない。実ランタイムへのMotorService配送と原点再設定操作は後続。
