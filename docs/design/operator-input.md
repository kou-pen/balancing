# 操作入力：通信断・復帰を安全に扱う

USB DualSenseとCAN_REMOTEの**操作量を扱う数学モデル**です。まだ実際のUSB HIDやCANフレームは読んでいません。

## 動作の流れ

<pre class="mermaid">
flowchart LR
    USB["USB DualSense：デコード済み入力"] --> SEL["明示的に選択された操作元"]
    CAN["CAN_REMOTE：デコード済み入力"] --> SEL
    SEL --> TIME["新規測定時刻と鮮度"]
    TIME --> NEUTRAL["復帰時ニュートラル確認"]
    NEUTRAL --> RATE["速度・Yaw変化率制限"]
    RATE --> TARGET["制御用の目標値"]
</pre>

**ARM要求はこのモジュールから発生させません。** 操作の復帰とモータ駆動許可は別の処理です。

## 重要な判断

| 状況 | 処理 |
|---|---|
| 初期状態 | USBを選択し、ニュートラルの確認が終わるまで入力を通さない |
| USB/CANの操作元切替 | DISARMED中の明示要求だけ受理。前回の入力を破棄 |
| 通信断 | 速度・Yaw目標をそれぞれ設定した変化率で0へ減速 |
| 通信復旧 | 複数の新規ニュートラル入力と継続時間を確認するまで再開しない |
| FAULT/DISARMED | 操作目標を即0にする。自動ARMしない |
| 過去時刻、NaN、不明な操作元 | 新しい入力として受け付けない |

## 検証の境界

入力はすでにm/s・rad/sへ変換された値です。実際のスティックHID番号、CAN_REMOTEのID/DLC、デッドゾーン、入力周期、許容速度は未確定であり、ホスト試験では人工値を使います。

受信イベントは一つの所有者が時系列に投入する前提です。割込みと制御ループの並列アクセスは実装していません。実CAN/USBと結合する前に、元の通信時刻を保持するアダプターと排他方法を検証します。
